Définition d'un agent et image mentale de l'infra finale

Un agent c'est quoi ?
Un agent = un programme qui reçoit un objectif, décide lui-même des étapes pour l'atteindre, exécute des actions dans le monde réel, et boucle jusqu'au résultat. Ce n'est pas un format de fichier ou un outil précis — c'est une architecture.
Les 4 ingrédients d'un agent
Un LLM qui décide — Claude API, GPT, Mistral. Il reçoit un objectif + contexte, il choisit quoi faire.
Des outils (tools) — actions que le LLM peut déclencher : appel API, lire un fichier, écrire en BDD, envoyer un message, naviguer sur une page.
Une boucle — il agit, observe le résultat, décide de la prochaine action, jusqu'à objectif atteint ou erreur.
Un état / mémoire — ce qu'il sait déjà (BDD, fichier JSON, Google Sheets). Pas la mémoire interne de Claude — c'est TOI qui la gères.

Un .md de prompt système c'est juste la description du rôle et des règles de l'agent — c'est utile pour Claude Code mais ce n'est pas ce qui "fait" un agent.
N8N, Dust — faut-il en avoir ?
N8N — orchestrateur de workflows visuels. Utile si tu veux connecter des services sans coder (Gmail → Sheets → Slack). Dans ton cas tu codes déjà en PHP, les webhooks tu les fais toi-même. N8N = couche supplémentaire sans valeur réelle pour toi pour l'instant.
Dust — plateforme d'agents d'entreprise. Trop cher, trop opinionated, fait pour des équipes pas pour un solo founder.
Ce dont tu as besoin à la place — un orchestrateur maison léger : un script PHP central qui planifie et déclenche tes agents. Simple, sous ton contrôle, 0 abonnement.
Image mentale — l'infra finale sur ton PC à la maison
Couche 0 — Hardware (ton PC fixe à la maison)
Ubuntu ou Windows + WSL2 · Docker Compose · accès SSH depuis partout · IP fixe OVH ou DynDNS
Couche 1 — Données & état (le cerveau persistant)
MySQL izilife local + replica · Google Sheets hub (planning éditorial, files d'attente agents) · Fichiers JSON /data/agents/ · Redis pour les queues légères
Couche 2 — Orchestrateur (le chef d'orchestre)
Script PHP central (ou Python) · Cron jobs planifiés · File de tâches : lieu à enrichir, event à processer, post à générer · Déclenche les agents au bon moment, log tout
Couche 3 — Les agents (les exécutants)
Agent enrichissement : PHP → Google Places API → Claude API (analyse diff) → _tmp
Agent curation events : Cowork (scroll) → PHP parse HTML → Claude API (OCR flyers) → _tmp
Agent WhatsApp : webhook → PHP → Claude API → _tmp
Agent réseaux : PHP → Claude API (génération) → Cowork ou Buffer API (publication)
Agent blog : PHP cron RSS → Claude API (rédaction) → WordPress API
Agent WordPress clients : Claude Code (SSH) → Git → deploy OVH
Ce que Claude in Chrome & Cowork font dans cette infra : ils sont des outils des agents de la couche 3 — quand un agent a besoin d'un navigateur humain pour une page dynamique, il délègue à Claude in Chrome. Cowork pour les publications. Tout le reste = scripts PHP directs.
